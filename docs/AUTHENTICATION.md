# Авторизация и поток запросов

В исходном репозитории был только README, поэтому прежней системы авторизации не было. Ниже описана реализация этой версии, а не устройство Zello.

## Компоненты

| Компонент | Файл | Назначение |
|---|---|---|
| Экран | `app/src/main/java/dev/khvylia/radio/MainActivity.java` | Проверяет поля и разрешение микрофона, управляет подключением, запросом эфира и жизненным циклом |
| Клиент | `app/src/main/java/dev/khvylia/radio/RadioClient.java` | TLS, JSON-протокол, AudioRecord/AudioTrack, ограниченные очереди |
| Ретранслятор | `server/radio_server.py` | Аутентификация, права на канал, арбитраж говорящего, пересылка PCM |
| Создание аккаунта | `server/create_account.py` | Генерирует 32 случайных байта через secrets, сохраняет SHA-256 ключа |

## Подключение

1. Пользователь вводит доменное имя, порт, канал и выданный администратором ключ. Имя участника берётся из серверного аккаунта, а не из неподтверждённого поля клиента.
2. `RadioClient.connect` открывает TCP, затем SSLSocket. Используется системное хранилище доверенных сертификатов и `setEndpointIdentificationAlgorithm("HTTPS")` для проверки имени сервера. Секрет отправляется только после успешного TLS handshake; отключения проверки сертификатов нет.
3. Первое JSON-сообщение — `auth` с полями `token` и `channel`. Сервер вычисляет SHA-256 токена, ищет аккаунт и проверяет точное присутствие канала в `channels`. При отказе закрывает соединение, не раскрывая, какая часть реквизитов была неверна.
4. Сервер отправляет `joined`, затем `state` со списком участников и текущим говорящим. Авторизованная сессия привязана к TLS-соединению и одному каналу.
5. Нажатие кнопки отправляет `claim`. Сервер выдаёт `granted` только при свободном канале, иначе `busy`. Микрофон запускается только после `granted` и пока пользователь продолжает удерживать кнопку.
6. Клиент отправляет JSON `audio` с Base64 PCM-кадром. Сервер принимает звук к пересылке только от владельца эфира и рассылает его другим участникам этого же канала. Чужой/опоздавший звук отбрасывается.
7. Отпускание кнопки отправляет `release`. 30-секундный серверный таймер и отключение также освобождают эфир. Клиент останавливает микрофон при `released`.
8. Клиент шлёт `ping` каждые 15 секунд, сервер отвечает `pong`; есть таймаут неактивности 45 секунд и максимальная длительность сессии 1 час.

## Пароли, ключи и токены

- Паролей, JWT, OAuth, refresh/access token пары и регистрации по телефону в MVP нет. Один персональный bearer-ключ даёт доступ к перечисленным в аккаунте каналам.
- Ключ состоит из 32 криптографически случайных байт в URL-safe Base64. `tokens.json` содержит только SHA-256 хеш, отображаемое имя и каналы. Хеширование без соли здесь применяется к высокоэнтропийному случайному ключу, не к человеческому паролю.
- На Android ключ не записывается в SharedPreferences, файлы, backup или сохранённое состояние поля. Он присутствует в памяти процесса во время соединения. Гарантированной очистки Java String из памяти нет.
- Адрес сервера, порт и канал сохраняются в приватных SharedPreferences; резервное копирование приложения отключено.
- Сервер загружает аккаунты при старте. Для отзыва/ротации измените файл и перезапустите сервер, завершив активные соединения.
- Ни токены, ни PCM не логируются и не сохраняются серверным кодом. Сервер расшифровывает транспорт и имеет доступ к звуку: **сквозного шифрования нет**.
- Секреты и закрытые ключи не входят в APK, GitHub Actions и исходники. CI имеет только `contents: read`; debug-подпись генерируется инструментами Android.

## Границы

Сервер доверенный. Нет защиты от записи звука другим участником, администратором или скомпрометированным устройством. TLS не скрывает метаданные трафика. Нужны дополнительная эксплуатационная защита и нагрузочные испытания перед открытием публичного сервиса.

Официальные материалы: [TLS в Android](https://developer.android.com/privacy-and-security/security-ssl), [AudioRecord](https://developer.android.com/reference/android/media/AudioRecord).
