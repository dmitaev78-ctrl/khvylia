# Хвиля — Android-рация

Первая версия независимого приложения push-to-talk, вдохновлённого сценарием использования Zello. Не использует сеть, аккаунты или протокол Zello.

## Возможности

- Нативное Android-приложение на Java, Android 8.0+ (API 26).
- Удерживайте кнопку для передачи; отпустите для прослушивания. Для экранного диктора — активация кнопки включает/выключает передачу.
- Серверные каналы с разрешённым списком для каждого пользователя, имена и список участников.
- Один говорящий в канале; максимум 30 секунд непрерывной передачи.
- TLS с проверкой цепочки сертификата и имени сервера; личный случайный ключ доступа.
- Отключение при сворачивании, потере аудиофокуса или сети. Автоматического переподключения нет.

**Это MVP, а не полный аналог Zello.** Нет фонового приёма, push-уведомлений, контактов, истории, Opus, сквозного шифрования и готового публичного сервера. Для разговора между двумя телефонами нужен запущенный сервер ниже. Сервер может читать пересылаемый звук; TLS защищает транспорт. Голос в файлы не сохраняется.

## Получить APK

Workflow [Android APK](../../actions) собирает `app/build/outputs/apk/debug/app-debug.apk` и публикует артефакт `khvylia-debug-apk`. Это тестовый APK с debug-подписью, не выпуск для Google Play. У новой CI-сборки может быть другой тестовый ключ подписи: тогда перед установкой потребуется удалить старую версию.

Локально: JDK 17, Android SDK Platform 35 / Build Tools 35.0.0, Gradle 8.11.1. В проекте AGP 8.9.2; Gradle Wrapper не включён. Установите указанную версию Gradle или создайте wrapper командой `gradle wrapper --gradle-version 8.11.1`.

```sh
gradle :app:assembleDebug :app:lintDebug
python3 -m unittest discover -s server -v
```

Совместимость версий проверена по [Android Developers](https://developer.android.com/build/releases/agp-8-9-0-release-notes).

## Запуск сервера

Нужен ваш сервер с Python 3.11+, доменное имя, открытый TCP-порт 8443 и действительный сертификат доверенного Android удостоверяющего центра для этого имени. Это отдельный TLS/TCP-протокол, не HTTP/WebSocket; обычный HTTP reverse proxy не подходит. Хостинг/домен могут быть платными. Самоподписанные сертификаты приложение не принимает. Тесты используют отдельный локальный сертификат только в тестовом клиенте.

1. Скопируйте каталог `server` на сервер. Создайте аккаунты (на сервере, не в публичном CI):

```sh
cd server
python3 create_account.py Denis general friends
python3 create_account.py Friend general
```

Скрипт один раз покажет личный ключ каждого пользователя. Передайте его соответствующему человеку приватно. В `tokens.json` сохраняются SHA-256 хеши, имена и разрешённые каналы; права файла — 0600. Не публикуйте этот файл, ключи, токены или закрытый ключ сертификата.

2. Запустите процесс от отдельного непривилегированного пользователя с доступом к сертификату и ключу:

```sh
python3 radio_server.py --cert /secure/fullchain.pem --key /secure/privkey.pem --accounts tokens.json --port 8443
```

Файлы сертификата должны содержать действующую цепочку и соответствующий приватный ключ. Настройте перезапуск процесса через менеджер служб вашего сервера. После обновления сертификата, изменения аккаунтов или отзыва ключа перезапустите процесс. Это завершит активные сессии. Для отзыва удалите запись пользователя из `tokens.json`; новый ключ создавайте после удаления старой записи.

3. На двух телефонах установите APK. Разрешите микрофон, введите одинаковые сервер/порт/канал и **разные личные ключи**. Нажмите «Подключиться». Используйте кнопки громкости для громкости воспроизведения.
4. Удерживайте кнопку на одном телефоне, слушайте на другом. Для проверки рядом используйте наушники во избежание акустической обратной связи.

Ключ телефона хранится только в памяти текущего подключения, очищается из поля после нажатия подключения. После отключения его нужно ввести снова. Сохраняются только адрес, порт и канал.

## Ограничения и проверки

Сервер: до 64 принятых соединений, ограниченные очереди и размер сообщений, одна сессия на имя, до 100 команд/сек, сессия до часа; затем нужно подключиться снова. Не предназначен для публичного сервиса большой нагрузки, защиты от DDoS или аварийной связи.

Аудио: PCM16 LE, 16 кГц, моно, кадр 20 мс (640 байт). Без сжатия: 16000 × 2 = 32000 байт/с; Base64 увеличивает это примерно до 42700 байт/с, плюс JSON/TLS/TCP. На слабой сети задержка может расти; медленные клиенты отключаются при переполнении очереди.

Автотесты проверяют реальные локальные TLS-соединения, неверные ключи/каналы, конкуренцию за эфир, передачу PCM, изоляцию каналов, таймаут передачи, отключение, неверные кадры, дубликат аккаунта и проверку имени сертификата. Эти тесты не подтверждают качество микрофона/динамика на физическом Android-устройстве. Ручная проверка на двух телефонах ещё необходима.
